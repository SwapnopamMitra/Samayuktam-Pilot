      02
      
How your license is enforced

    

    

      

        
ENCRYPTION

        
AES-256-GCM

        
License state encrypted at rest and in memory. Authenticated cipher — tampering breaks the tag, not just the plaintext.

      

      

        
BINDING

        
Hardware fingerprint

        
Machine ID, MAC, and CPU identity hashed into one binding key at issuance. Move the binary to another machine, it stops running.

      

      

        
DETECTION

        
VM / debugger scan

        
Checked before license decrypt. A scoped deterrent against casual extraction — not a copy-protection promise.

      

      

        
AVAILABILITY

        
Online-only. No exceptions.

        
Every run performs a signed round-trip to our licensing server before any work happens. The server's count is the final word. No offline mode. No grace period. Server unreachable — run refused. The count that matters lives on our infrastructure, not on your disk.

      

      

        
SYSTEM ACCESS

        
Exactly what touches your machine

        
Reads (once, at bind time): machine ID, primary NIC MAC, and two fields from /proc/cpuinfo. Network: the binary calls our licensing server directly — once to activate on first launch, then again on every subsequent run to check remaining uses. Both calls are automatic; there is nothing for you to run or configure. Nothing else is read, written, or modified. No local state files. No background service.

      

      

        
ENVIRONMENTS

        
Verified: WSL2 & Google Colab

        
Both binaries have been run and verified on WSL2 and Google Colab. Snapshot/revert-style VMs are unsupported — reverting a snapshot breaks the fingerprint assumption by design.
        


        WSL2: confirm your virtual NIC MAC doesn't regenerate on restart before requesting a license. Run the MAC command, do a full wsl --shutdown, reopen, and compare. If it changes, flag it when you write in.
        


        Colab: container recycling (idle timeout, disconnect, restart) can produce a different MAC or machine ID and fail the fingerprint check. Fine for a single-session pilot run — not for multi-session use.

      03
      
What CAGM actually does

    

    

      

        
ARCHITECTURE

        
Fixed-point residual network

        
Four-layer fully-connected classifier running entirely in integer arithmetic. No floating point in the training loop.

      

      

        
DETERMINISM

        
Integrity Engine (IE)

        
Canonicalizes logits at layer boundaries — NaNs and negative zero mapped to fixed bit patterns — so the same run hashes identically across compilers and hardware.

      

      

        
PROOF

        
SHA-256 trajectory proof

        
Weight, gradient, and activation traces reduced to a single 64-character hex proof. Deterministic across machines.

      

      

        
OUTPUT CONTRACT

        
stdout only

        
accuracy, proof, and ie_verify — in that order, on stdout. Everything else stays on stderr.

      

    

    

      Internal constants are withheld. This is the architecture, not the parameters. Full specification available on request.
    

  


  
  

    

      04
      
What SPCMP actually does

    

    

      

        
ORDERING

        
Canonical float32 ordering

        
Every IEEE-754 binary32 value bijectively mapped to a uint32 and ordered by unsigned comparison — one deterministic total order across NaNs, infinities, signed zero, and subnormals.

      

      

        
PREPROCESSING

        
Lossy canonicalization

        
NaN payloads collapse to one canonical quiet NaN; −0.0 collapses to +0.0. Deliberate and irreversible for those two edge cases.

      

      

        
ENCODING

        
Predictive transform + Zstd

        
Delta prediction on mapped values, then Zstandard compression. Reversible permutation stored alongside for exact reconstruction of original element order.

      

      

        
VERIFICATION

        
Fail-closed, SHA-256 bound

        
Hash checked before any inverse transform runs. Mismatch is a hard failure — no partial output, no silent recovery.

      

    

    

      SPCMP is a frozen profile of PCMP v1. Version 1 semantics don't change — anything different needs a new profile identifier.
