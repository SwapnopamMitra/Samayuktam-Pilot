      02
      
How your license is enforced

    

    

      

        
ENCRYPTION

        
AES-256-GCM

        
License state encrypted at rest and in memory. Authenticated cipher — tampering breaks the tag, not just the plaintext.

      

      

        
INTEGRITY

        
Ratchet chain + witness anchors

        
Each verification step advances the chain. Four independent witness anchors outside the state tree — one root-owned, three user-space — cross-check use count on every run. Any anchor missing or behind is a hard fail, no exceptions.

      

      

        
BINDING

        
Hardware fingerprint

        
MAC, machine ID, and CPU identity hashed into one binding key at issuance. Move the binary, it stops running.

      

      

        
DETECTION

        
VM / debugger scan

        
Checked before license decrypt on shipped binaries. Not a copy-protection promise — a scoped deterrent against casual extraction.

      

      

        
AVAILABILITY · DEFAULT PATH

        
Live server check

        
Every single run performs a signed round-trip to our licensing server before any work happens — the server's own high-water-mark count is the final word, independent of anything stored on your machine. This is the path we build, test, and recommend. There is no offline mode and no grace period: if the server is unreachable, the run is refused, by design, not as a fallback. It also means enforcement isn't sitting on your hardware waiting to be reverse-engineered — the count that matters lives on our infrastructure, not in a file on your disk.

      

      

        
AVAILABILITY · LEGACY, OPTIONAL

        
TPM hardware counter

        
On TPM-equipped machines, a monotonic hardware counter can also be provisioned via tpm_setup_spcmp.sh — a value that survives file deletion, OS reinstalls, and full disk wipes, resetting only via physical TPM2_Clear. We do not recommend enabling this for pilot or production use. It depends on tpm2-tools, firmware TPM state, and NV-index provisioning that vary by hardware vendor and BIOS revision — failure modes here are materially harder to diagnose remotely than a single rejected HTTPS call. Unless your license was explicitly issued with hardware binding required, treat this as off.

      

      

        
ENVIRONMENTS

        
Verified: WSL2 & Google Colab

        
Both CAGM and SPCMP have been run and verified end-to-end on WSL2 and on Google Colab — no virtualization workarounds needed to evaluate the pilot. This is narrower than "any VM": snapshot/revert-style VMs (VirtualBox, VMware images you roll back) remain unsupported, since the machine fingerprint assumes stable identity, and reverting a snapshot deliberately breaks that assumption.
        


        WSL2 users, one thing to check first: depending on your Windows build and network mode, WSL2's virtual network adapter can regenerate a new MAC address on restart — which would break your binding through no fault of ours or yours. Before requesting a license, confirm yours doesn't: run cat /sys/class/net/eth0/address, fully restart WSL (wsl --shutdown from PowerShell, then reopen — a same-session re-run won't tell you anything), and compare. Repeat once more after a sleep/wake cycle, since that can trigger the same reset independently of a restart. If the value ever changes, tell us when you request your license so we address it up front instead of after a break.
        


        Colab users, know this going in: Colab recycles your underlying container on its own schedule — idle timeout, disconnect, or a plain runtime restart — not just when you deliberately roll back a snapshot. Since the binding depends on state that lives on that container's disk, a recycle you didn't ask for can land you in the same "prior enrollment detected" state as a manual revert. This isn't a bug we're planning to patch out; it's a direct consequence of binding license state to ephemeral compute, and no DRM scheme can fully paper over it. If continuous, long-running evaluation matters to you, a persistent VM or dedicated machine avoids this entirely — Colab is fine for a short, single-session pilot run, less so for anything spanning multiple sessions over days.

      

      

        
SYSTEM ACCESS

        
Exactly what touches your machine

        
Reads (once, to compute your binding): your primary NIC's MAC address, /etc/machine-id, and four fields from /proc/cpuinfo. Writes: your license state (install3.id, ratchet.log, state3.dat, blob3.dat, mito.log) lives in the same directory as the binary itself — nothing is placed in a hidden home-directory path. Alongside that, four independent witness anchors cross-check use count outside the state files — one root-owned file under /etc/samayuktam/, and three user-space anchors under ~/.cache/, ~/.config/, and, on WSL, a Windows-side file under your user's AppData\Local\...\INetCache folder. Full paths and a complete removal command are in Troubleshooting, below. Network: HTTPS only, to one Cloudflare Worker endpoint (drm3-redeem.samayuktam.workers.dev). Nothing else on the machine is read, written, or modified — no registry, no background service.

      

    


    
Troubleshooting

    

      

        
T1

        
"License commit rejected by server"

        curl -sSf https://drm3-redeem.samayuktam.workers.dev/redeem
        
Confirms the endpoint is reachable from your machine. One Worker serves both CAGM and SPCMP at this single URL — there's no separate per-product endpoint to check. If this hangs or fails, it's your network path (firewall, proxy, offline), not your license — remaining uses stay frozen until a run succeeds end to end.

      

      

        
T2

        
"License integrity violation — prior enrollment detected"

        ls -la /etc/samayuktam
        
Expected the first time you run on a machine that's already enrolled — moving, cloning, or restoring files does not reset this. Do not delete or relocate anchor files yourself; contact us if you believe this is wrong.

      

      

        
T3

        
"No TPM device found" during setup

        ls /dev/tpm0 /dev/tpmrm0
        
Expected on most machines, including WSL2 and Colab. The app runs on the server-side check alone with no loss of enforcement — the TPM counter is a legacy, optional layer we don't recommend enabling, not a hard requirement, unless your license was specifically issued with hardware binding.

      

      

        
T4

        
TPM counter increment fails

        sudo tpm_setup_spcmp.sh
        
Usually tpm2-tools missing or the NV index owner auth doesn't match. Since this path is optional and legacy, our default guidance is to leave it disabled rather than debug it — re-run the setup script as root only if your license was issued requiring hardware binding.

      

      

        
T5

        
Cycle mismatch after system restore

        samayuktam.licensing@gmail.com
        
If you've restored from a backup and the binary reports a cycle mismatch, your local state is out of sync with the license server. Email your logs to samayuktam.licensing@gmail.com for a reissue with your remaining uses intact.

      

      

        
T6

        
Fully removing DRM3 (uninstall)

        rm -f ~/.cache/.smy-*
rm -f ~/.config/.sy3-*.dat
rm -f /mnt/c/Users/<you>/AppData/Local/Microsoft/Windows/INetCache/.sy3w-*

sudo rm -rf /etc/samayuktam

# then, from the folder containing your binary:
rm -f install3.id ratchet.log state3.dat blob3.dat mito.log
        
Everything DRM3 writes lives in exactly these locations: the license state files sitting next to the binary itself, the root-owned anchor, and three user-space witness anchors that independently cross-check use count. Delete all of it and every trace is gone. Delete only some of it and re-run, and you'll get a hard integrity failure — that's the witness system correctly detecting a partial wipe, not a bug.

      

    

  


  

    

      03
      
What CAGM actually does

    

    

      

        
ARCHITECTURE

        
Fixed-point residual network

        
A four-layer fully-connected classifier running entirely in integer arithmetic — no floating point anywhere in the training loop. Residual adds carry L1 and L2 output forward into L2 and L3.

      

      

        
DETERMINISM

        
Integrity Engine (IE)

        
Canonicalizes floating-point logits at layer boundaries — NaNs mapped to one bit pattern, negative zero mapped to positive zero — so the same run hashes identically across compilers and hardware.

      

      

        
PROOF

        
SHA-256 trajectory proof

        
Weight, gradient, and activation traces are each reduced to a Merkle root; a blockchain-style gradient chain links every epoch to the last. All of it combines into one 64-character hex proof.

      

      

        
CONTRACT

        
stdout output contract

        
accuracy, proof, and ie_verify print to stdout in that order. Everything else — epoch progress, warnings — stays on stderr.

      

    

    

      Internal constants — init seeds, quantization steps, hyperparameter bounds — are withheld under the pending patent filing. This is the architecture, not the parameters.
    

  


  

    

      04
      
What SPCMP actually does

    

    

      

        
ORDERING

        
Canonical float32 ordering

        
Every IEEE-754 binary32 value is bijectively mapped to a uint32 and ordered by unsigned comparison — one deterministic total order covering NaNs, infinities, signed zero, and subnormals.

      

      

        
PREPROCESSING

        
Lossy canonicalization

        
All NaN payloads collapse to one canonical quiet NaN, and −0.0 collapses to +0.0, before ordering. Deliberate and irreversible for those two edge cases — not a bug.

      

      

        
ENCODING

        
Predictive transform + Zstd

        
Order-0/1/2 delta prediction runs on the mapped values, then Zstandard compression. A reversible permutation is stored alongside so the original element order can be reconstructed exactly.

      

      

        
VERIFICATION

        
Fail-closed, SHA-256 bound

        
The hash covers the uncompressed predictive stream and is checked before any inverse transform runs. Any mismatch is a hard failure — no partial output, no silent recovery.

      

    

    

      SPCMP is a strict, frozen profile of PCMP v1. Version 1 semantics don't change; anything different needs a new profile identifier.
